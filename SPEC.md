# SPEC: Tattoo Fitting Room (3d-body-editor, v2)

Примерочная татуировок: пользователь настраивает 3D-тело под свои параметры, наносит татуировки (свои PNG или из библиотеки), добавляет старые и смотрит, как всё сочетается.

Решение по старому репозиторию: он содержит только шаблон React + Vite (1 коммит, без 3D), поэтому начинаем с чистого листа в том же репозитории.

## 1. Решения по результатам опроса

| Тема | Решение |
|---|---|
| Модель тела | MakeHuman/MPFB (CC0), экспорт в glTF с morph targets |
| Нанесение | Клик по телу + перетаскивание, поворот, масштаб |
| Свои татуировки | PNG с прозрачностью |
| Хранение | Без бэкенда. Всё в браузере (IndexedDB), экспорт/импорт файлом |
| Слои | Много слоёв, пометка «старая», сравнение до/после, undo/redo |
| Библиотека | Небольшой набор CC0, 10–20 рисунков |
| Вывод | Скриншот PNG, файл проекта JSON, ссылка для шаринга |
| Устройства | Только десктоп |

## 2. Функции MVP

### 2.1 Тело
- Параметры: пол, рост, вес, мышечность, возраст (слайдеры), цвет кожи.
- Параметры управляют morph targets. Мгновенный отклик (< 50 мс на слайдер).
- Орбитальная камера, пресеты видов: спереди, сзади, слева, справа.

### 2.2 Татуировки
- Загрузка PNG (до 5 МБ, до 2048 px по длинной стороне; больше сжимаем).
- Библиотека готовых.
- Клик по телу ставит татуировку в эту точку, перетаскивание двигает её по поверхности.
- Ручки: масштаб, поворот, прозрачность, отражение.
- Панель слоёв: порядок, скрыть, удалить, пометка «старая».
- «Старая» — отдельный набор слоёв, которые не удаляются случайно и переключаются отдельно от новых.
- Сравнение: «до» (только старые) / «после» (старые + новые).
- Undo/redo для всех действий над слоями и параметрами тела.

### 2.3 Вывод
- Скриншот PNG (текущий вид, без UI).
- Проект в `.json` (параметры тела, слои, встроенные PNG в base64) и импорт обратно.
- Ссылка для шаринга: **без бэкенда** кодирует только параметры тела и слои из библиотеки (id + позиция) в hash URL. Свои PNG в ссылку не входят, это ограничение показывается пользователю. Полноценный шаринг — этап 2 вместе с бэкендом.

### 2.4 Не входит в MVP
Аккаунты, мобильные устройства, рисование кистью, фото-сегментация старых тату, облачная библиотека.

## 3. Архитектура («элегантное» решение)

Ключевая идея: **тело — это функция от параметров, татуировки живут в UV-пространстве тела, а не в 3D-пространстве.**

- Тату хранится как `{ imageId, u, v, widthCm, frame, rotation, opacity, mirrored, old, visible }`. `widthCm` — реальная ширина; `frame` — сколько UV приходится на метр поверхности вправо и вверх в точке тату (считается по треугольнику под курсором, см. `src/tattoo/uvFrame.ts`). Благодаря этому размер и вертикаль сохраняются на любом участке неравномерной UV-развёртки.
- Клик по телу: raycast даёт UV-координату попадания. Дальше 3D не используется.
- Все видимые слои компонуются в **один canvas-текстуру** (2D canvas = UV-развёртка кожи) и подаются в материал как `map`.
- Morph targets не меняют UV, поэтому татуировки сами «едут» за телом при смене веса или роста. Не нужно пересчитывать декали.
- Один материал, один draw call, не зависит от числа слоёв.
- Состояние — единое неизменяемое дерево (`BodyParams` + `Layer[]`). Undo/redo — стек снапшотов. Сохранение, шаринг и скриншот — функции от этого состояния.

```
state (params, layers)  ──►  compose(layers) → CanvasTexture ──►  Three.js scene
        ▲                                                              │
   UI / input  ◄───────────── raycast → (u, v) ◄───────────────────────┘
```

## 5. Подводные камни

1. **Швы и растяжение UV.** Тату у шва UV-острова (боковая поверхность, подмышки, пах) рвётся или растягивается. Нужны: компенсация масштаба по локальной плотности UV и перенос части рисунка за шов.
2. **Лицензия и качество модели.** MakeHuman-экспорт даёт тяжёлую сетку и UV, не рассчитанные на тату. Нужны оптимизация (decimate) и проверка CC0 для каждого ассета.
3. **Размер текстуры и память.** Canvas 4096×4096 пересобирается при каждом drag. Нужны: двойная буферизация, пересборка только изменённой области, 2048 по умолчанию.
4. **Morph targets и производительность.** Много морфов одновременно на тяжёлой сетке нагружают GPU. Нужен бюджет: не больше N активных морфов.
5. **Хранение.** IndexedDB может быть очищен браузером; PNG в base64 раздувают JSON. Нужны предупреждение и явный экспорт.
6. **Ссылка для шаринга** без бэкенда ограничена по длине (~2000 символов) и не содержит свои PNG.
7. **Согласие и контент.** Пользовательские фото тела — персональные данные; всё обрабатывается только локально, на сервер ничего не уходит. Это нужно зафиксировать в интерфейсе.
8. **Масштаб реального размера.** Тату должна иметь размер в сантиметрах, а не в UV. Нужно хранить `scale` в см и пересчитывать по росту тела.

## 6. Три причины, почему это провалится

1. **UV-подход даст артефакты на самых популярных зонах** (плечо, бок, предплечье вокруг, шея), и пользователь решит, что «выглядит криво». Проверять надо сразу на прототипе из 3 зон, до всего остального UI.
2. **Модель окажется непригодной**: тяжёлая, с «уродливыми» морфами на крайних значениях слайдеров или с лицензионными нюансами. Выбор и подготовка модели — самый рискованный этап; на него закладывается первая неделя, а не последняя.
3. **Подмена цели «примерочная» на «редактор»**: проект уже раз застрял в «каше». Если сразу не отрезать рисование, фото-сегментацию, бэкенд и мобильные устройства, MVP не будет закончен. Защита: список «не входит в MVP» (п. 2.4) и релиз вертикального среза в первую очередь.

## 7. Проверка (как докажем, что работает)

Сейчас кода нет, поэтому доказывать нечего: тесты и результаты их запуска появятся после реализации. Критерии приёмки:

- `compose.ts`: слои → пиксели совпадают с эталоном (юнит-тест).
- `serialize.ts`: round-trip проект → JSON → проект идентичен; hash-ссылка < 2000 символов для 10 слоёв; битый файл отклоняется Zod-схемой.
- `params.ts`: границы слайдеров дают валидные веса [0..1].
- e2e (Playwright): загрузить PNG → клик по плечу → слой появился → изменить вес → тату осталась на плече → скриншот не пуст.
- Ручная проверка: 3 зоны (плечо, предплечье, спина), без видимых разрывов.
